# 登录注册安全加固学习：限流 + 锁号 + 滑块验证码

> 记录本项目防暴力破解/防机器刷注册的方案选型与实现细节。
> 按项目约定：每次技术选型均生成一份记录文档（见 `docs/` 目录）。

## 1. 威胁模型

- **登录暴力破解**：机器人对 `/login` 高速穷举密码（每秒数百次）
- **机器批量注册**：脚本对 `/users` 疯狂建垃圾账号
- **低频字典攻击**：慢速猜密码，绕过简单限流

## 2. 行内防御工具箱

| 手段 | 证明什么 | 强度 | 成本 | 备注 |
|---|---|---|---|---|
| 字符验证码 | 是人 | 弱（AI 识别率 99%+） | 免费 | 淘汰中 |
| 滑块/拖拽（腾讯验证码、极验） | 是人（看轨迹） | 中上 | 免费额度 | 国内主流 |
| 短信验证码 | 实名真人 | 最强 | ~5分/条 | 需企业资质，个人难批 |
| 邮箱验证 | 邮箱存在 | 弱 | 免费 | 辅助 |
| 无感风控（reCAPTCHA v3） | 行为像人 | 中 | 免费 | 国内加载不稳 |
| 限流 + IP 信誉 + 账户锁 | — | 基础兜底 | 免费 | 必做 |

行内标准组合：

- **注册** = 滑块（挡脚本）+ 短信（挡真人黑产，成本从电费变实名号成本）
- **登录** = 风险分级验证：平时零验证，失败 2-3 次弹滑块，再犯锁号

### 手段详解

**① 字符/图形验证码**

- 原理：扭曲字符/算术题，用户输入
- 现状：深度学习 OCR 识别率 99%+，黑产打码平台几分钱解千次，**行内已淘汰**，仅存于老系统

**② 滑块/拖拽验证码（国内主流）**

- 原理：拖滑块把拼图嵌入缺口；后端不止看结果坐标，还分析**拖动轨迹**（速度曲线、抖动、停顿）区分人机
- 厂商：腾讯验证码、极验（GeeTest）、网易易盾；均有免费额度，个人开发者可接
- 强度：中上；挡普通脚本足够，专业打码平台可过（人工接单约 1 元/千次）
- 适用：注册、登录二次验证、领券/下单防刷

**③ 点选验证码**

- 原理：按顺序点击图中汉字/图标（极验代表）；比滑块多一步语义理解，机器更难
- 强度：略高于滑块；代价是用户体验稍差（移动端点不准）

**④ 短信验证码（终极武器）**

- 原理：手机号国内实名，批量注册成本从"电费"变"买实名号的钱 + 法律风险"
- 强度：**最强**，黑产算完账直接放弃
- 代价：约 5 分/条；阿里云/腾讯云签名审核基本要**企业资质**，个人主体难批
- 适用：有主体、有预算、注册开放给公众的产品

**⑤ 邮箱验证**

- 原理：发激活链接/验证码，证明邮箱存在
- 强度：弱（临时邮箱、批量邮箱成本低），但**免费**且海外习惯
- 适用：辅助层、海外产品主验证

**⑥ 无感风控（reCAPTCHA v3 / hCaptcha）**

- 原理：不打扰用户，后台根据浏览行为打分（0~1），低分才弹验证或直接拒
- 强度：中；体验最好
- 代价：国内加载不稳（Google 域名）；hCaptcha 可替代但生态小；隐私合规争议（GDPR）
- 适用：海外产品主流选择

**⑦ 设备指纹 + IP 信誉库**

- 原理：浏览器指纹（canvas/字体/UA 组合）+ 第三方 IP 风险库（机房 IP、代理池、秒拨机）
- 定位：**辅助层**，不单独做人机判定，用于提高脚本成本、给风控打分

**⑧ 蜜罐（Honeypot）**

- 原理：表单里放人类看不见、脚本会填的隐藏字段；填了即判机器
- 强度：只挡最 naive 的脚本，**零成本零感知**，常作免费加菜

## 3. 本项目落地（五层）

1. **限流**（Parse `rateLimit`）：`/login`、`/functions/register` 每 IP 每分钟 10 次，`/functions/smsSend` 5 次 → 高速穷举/刷短信直接废
2. **账户锁**（`accountLockout`）：连续错 5 次锁 15 分钟 → 低频字典攻击废
3. **密码策略**（`passwordPolicy`）：最少 8 位 → 防弱密码被秒破
4. **注册入口收口**：`beforeSave('_User')` 拦截非 master key 建号（v9 已移除 allowClientUserCreation），唯一入口 = Cloud 函数 `register`
5. **人机 + 实名双重验证**（均为阿里云号码认证服务，同产品族同账单）：
   - **图形认证**：前端 ct4.js SDK（滑动拼图/点选等形态由阿里云策略下发），验证通过后服务端用 appKey 对 lot_number 做 HMAC-SHA256 签名调 `https://captcha.alicaptcha.com/validate` 二次校验。**当前状态：临时停用**（开关置 false），恢复方式见第 4 节
   - **短信验证码**：`SendSmsVerifyCode`（##code## 阿里云生码）+ `CheckSmsVerifyCode` 托管校验，本端不存码

## 4. 选型变更记录：自研滑块 → 阿里云图形认证

- **背景**：初版为教学自研滑块（SVG 缺口图 + 前端拖拽），缺口坐标可被解析，挡不住会读图的定向攻击者；行内生产产品不用自研滑块
- **候选**：阿里云验证码 2.0 / 极验 / 腾讯天御 / 阿里云号码认证服务-图形认证
- **结论**：选**号码认证服务-图形认证**——与短信验证码同产品族，一个控制台一套账单；前端 ct4.js 自托管、后端一个 HTTP 验签接口，无额外 SDK 依赖
- **临时停用（开关式，非删代码）**：前后端各有一个 `GRAPHIC_CAPTCHA_ENABLED` 开关（前端 `RegisterPage/index.jsx` + 后端 `cloud/aliyun-captcha.js`），当前均为 `false`——注册跳过图形认证弹窗、服务端跳过二次校验，仅保留短信验证。恢复：两处开关同步置 `true` 即可，appId/appKey/ct4.js 均已就位无需重配
- **边界**：二次校验接口异常时按官方建议放行（不阻断业务）；ct4.js 需从控制台下载后自托管（public/ct4.js），不可本地魔改
- **升级路径**：遭遇定向攻击时可同控制台切换验证形态（点选/九宫格），或升级阿里云验证码 2.0 无痕验证，架构不变

## 5. 第三方验证码服务对比（行内真正在用的）

行内不用自研滑块。面向真实攻击的产品全部买服务，主流选择：

| 服务 | 形态 | 强度 | 成本 | 备注 |
|---|---|---|---|---|
| **极验 GeeTest 4.0** | 滑块/点选/图标 | 强 | 免费试用 + 按次付费 | 国内份额第一，文档教程最多 |
| **腾讯验证码（天御）** | 滑块/拼图 | 强 | 基础版有免费额度 | 有腾讯云账号顺手开通 |
| **网易易盾** | 滑块/点选/无感 | 强 | 免费试用 + 付费 | 游戏/社交行业用得多 |
| **阿里云验证码 2.0** | 滑块/无痕 | 强 | 按量付费 | **本项目已在阿里云生态（ECS/OSS），开通与计费最顺** |
| **Cloudflare Turnstile** | 无感/托管挑战 | 中强 | **完全免费** | 海外主流；国内加载不稳 |
| **Google reCAPTCHA v3** | 无感评分 | 中 | 免费 | 国内常连不上 |
| **hCaptcha** | 滑块/点选 | 中 | 免费 | 生态小，reCAPTCHA 替代项 |
| **aj-captcha（开源自持）** | 滑块/点选 | 中弱 | 免费 | Java 实现，要求数据不出机的团队用 |

第三方比自研强在三点：

1. **轨迹建模**：不止看终点坐标，分析整段拖拽的速度/加速度/抖动/停顿；打码平台就算人工接单也要模拟轨迹，成本抬高
2. **设备指纹 + 风险情报**：模拟器、代理 IP、机房段在验证码之前就被识别拦截
3. **持续对抗**：厂商有专门团队跟打码平台/脚本对抗升级，自研是"一次性"的

本项目初版自研滑块的定位：**教学版**——零依赖、完整演示"下发→交互→校验"链路；已于选型变更后升级为阿里云图形认证（见第 4 节）。

### 第三方接入实际接法（已落地）

1. 号码认证控制台新增图形认证方案，拿 appId（前端）+ appKey（后端）
2. 控制台下载 ct4.js 自托管到 `ecs-frontend/public/ct4.js`，index.html 引入
3. 前端 RegisterPage：`initAlicom4` 初始化，表单校验通过后 `showCaptcha()`，`onSuccess` 拿四要素（lot_number/captcha_output/pass_token/gen_time）随 register 提交
4. 后端 `register`：HMAC-SHA256(appKey, lot_number) 签名后调二次校验接口，通过才继续短信核验 + 建号

## 6. 关键代码位置

- 服务端配置：`index.js`（rateLimit / accountLockout / passwordPolicy）
- Cloud 入口（beforeSave 收口 + register/smsSend）：`cloud/main.js`；第三方集成抽离：`cloud/aliyun-sms.js`（短信发送/托管校验/错误码中文化）、`cloud/aliyun-captcha.js`（图形认证二次校验 + GRAPHIC_CAPTCHA_ENABLED 开关）
- 前端注册页（ct4.js 初始化 + 短信倒计时）：`ecs-frontend/src/pages/RegisterPage/index.jsx`
- 图形认证 SDK 自托管：`ecs-frontend/public/ct4.js` + `index.html` 引入
- 错误提示中文化：`ecs-frontend/src/lib/errorMsg.js`（Parse 内置英文文案 → 中文映射层，锁号时长从原文提取；服务端自定义文案已是中文直接透传）

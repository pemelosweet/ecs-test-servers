# 注册短信验证码选型记录（阿里云号码认证服务）

> 结论先行：注册流程在滑块之外叠加**短信验证码**，采用阿里云**号码认证服务（PNVS / dypnsapi）**的 `SendSmsVerifyCode` + `CheckSmsVerifyCode`，验证码由阿里云生成并**托管校验**，本端不存码。

## 1. 需求与威胁模型背景

- 滑块验证码（自研版）能挡脚本批量注册，但缺口坐标可被解析，对"会读图的定向攻击"防御有限。
- 短信验证码把注册成本从"零"抬到"每个账号一张真实手机卡"，是行内对抗批量注册的终极手段：
  - 接码平台成本（几毛到几元/号）直接劝退批量注册；
  - 手机号天然唯一，为后续风控（一号一号）打基础。
- 短信是要花钱的（按运营商回执计费，约 4~5 分/条），所以必须放在滑块**之后**作为第二道闸，并用多层流控防刷。

## 2. 候选方案对比

| 方案 | 原理 | 强度 | 成本 | 适用 |
|---|---|---|---|---|
| **阿里云短信服务（dysmsapi）** | 传统短信通道，自建签名/模板审核，自己存码自己校验 | 强 | ~0.045 元/条 | 通用短信场景，签名审核周期长 |
| **阿里云号码认证服务（dypnsapi）** ✅ | 短信认证子功能：系统赠送签名/模板免审核，验证码可由 API 生成并托管校验 | 强 | 仅短信费（核验免费） | 注册/登录验证码，快速接入 |
| 腾讯云短信 | 同上，腾讯系 | 强 | ~0.04 元/条 | 腾讯生态项目 |
| 邮箱验证码 | 免费但邮箱可无限注册 | 弱 | 免费 | 海外产品、低安全场景 |
| 语音验证码 | 电话播报验证码 | 强 | 更贵 | 短信到达率兜底 |

## 3. 行内最优结论

行内主流 = **滑块/行为验证（免费挡量）+ 短信验证码（付费挡质）** 组合。短信服务商选云厂商自家产品（阿里云/腾讯云），原因是同账号账单、RAM 权限体系统一、到达率有保障。本项目 ECS/OSS 都在阿里云，选**阿里云号码认证服务**最顺：

- 赠送签名/模板**免审核**，当天可用（传统短信服务签名审核要 1~2 天）；
- `##code##` 模式下验证码由阿里云生成，`CheckSmsVerifyCode` 托管校验，**本端无需存码、无需管过期**；
- 核验接口免费，只有发送计费；
- 与 OSS 复用同一套 AK 管理体系。

## 4. 本项目落地方案

**流程**（注册页共 3 道验证）：

```
用户名/密码 → 手机号 → 获取验证码（smsSend）→ 滑块对齐 → 提交注册（register）
                          │                                    │
                          ▼                                    ▼
              SendSmsVerifyCode(##code##)        CheckSmsVerifyCode(手机号+验证码)
              60s 间隔 / 300s 有效 / 旧码覆盖      VerifyResult=PASS 才建号
```

**防御层次**（从外到内）：

| 层 | 位置 | 规则 |
|---|---|---|
| IP 限流 | index.js rateLimit | `/functions/smsSend` 5 次/分钟/IP |
| 号码频控 | 阿里云侧 | 同号 60 秒一次（Interval）、300 秒有效（ValidTime）、重发旧码失效（DuplicatePolicy=1） |
| 天级上限 | 阿里云侧 + 本端 | 阿里云号码天级流控；本端内存 Map 同号 10 条/天 |
| 滑块前置 | 前端 + register | 先过滑块才轮到短信（UI 顺序约束；攻击者刷短信仍需先过滑块与 IP 限流） |
| 托管校验 | register | 验证码正确才 master key 建号，手机号写入 user.phone |

**凭证与配置**（.env，勿提交）：

```
ALIBABA_CLOUD_ACCESS_KEY_ID / ALIBABA_CLOUD_ACCESS_KEY_SECRET   # RAM AK
SMS_SIGN_NAME        # 号码认证控制台"赠送签名"页选择的签名
SMS_TEMPLATE_CODE    # "赠送模板"页选择的模板 CODE
SMS_SCHEME_NAME      # 可选，方案名（发送与校验必须一致，不填=默认方案）
```

> ⚠️ 生产 .env 由 GitHub Secret `PROD_ENV` 下发：新增的 4 个变量必须同步更新到 ecs-frontend 仓库的 PROD_ENV secret，否则线上短信功能报"短信服务未配置"。

## 5. 已知边界与升级路径

- **内存天级计数**：本端 10 条/天的计数存内存，后端重启清零（阿里云侧的天级流控不受影响，兜底仍在）。
- **短信轰炸风险**：攻击者可拿不同号码刷短信（每号 1 条不触发频控），靠 IP 限流 5 次/分钟压制；真遭遇时可升级为图形验证码前置 + IP 天级预算。
- **到达率**：个别号码收不到是运营商问题，可后续叠加语音验证码兜底（同 API 体系）。
- **升级路径**：需要"本机号码一键登录"（免输号码+验证码）时，同一 SDK 换 `GetPhoneWithToken` 接口即可，前端接号码认证 SDK 取 token。

## 6. 关键代码位置

- 后端短信模块：`cloud/main.js`（smsSend / verifySmsCode / register 双重校验）
- IP 限流：`index.js` rateLimit（smsSend 5/min）
- 前端：`ecs-frontend/src/pages/RegisterPage/index.jsx`（手机号 + 验证码 + 60s 倒计时）
- 错误中文化：短信错误码已在 cloud 端直接转中文，前端 zhError 透传
- 配置模板：`.env.example`（ALIBABA_CLOUD_* / SMS_* 段）
